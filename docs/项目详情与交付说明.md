## 3. 功能与改动

### 3.1 左上角攻略与修改器入口

local3 删除右侧常驻栏，恢复 SDL 游戏画面的全宽全高。左上角保留单个半透明工具图标，24dp 图案、48dp 触控区域，考虑系统栏和刘海避让，默认收起。

点击工具图标，通过 Android 原生 `PopupMenu` 选择攻略或修改器。攻略进入 `GuideActivity`；修改器保留既有原生线程路由，调用游戏内作弊界面，不把引擎操作直接放到 Android UI 线程。这是既有修改能力的入口整合，不是任意剧情或存档编辑器。

### 3.2 离线主线攻略

- `docs/full-walkthrough.md` 整理启程、长安、别离村、唐门、翠烟门、天王岛、中都、武林大会、被囚复仇、天忍教与结局等主线阶段。
- `docs/guide-content.md` 补充资源与脚本对应的阶段速览、易错过事项、触屏操作、作弊及剧情风险。
- `tools/assemble_offline_guide.py` 合并上述资料与来源链接，形成 APK 内的 `assets/engine/guide/guide.txt`。LOCAL3 记录整合文本约 10036 字符。
- 文本是社区资料的重新编排摘要，不复制原图或长段原文，不保证全部支线、所有结局分支或不同原版/白金版细节适用。

**全主线整理不等于已经通关验证。** 完整流程未在本地改造版逐步游玩核验。简明攻略引用的任务标志、脚本断言或 `HappyEnding=1` 判据也不能替代完整实机通关结果。简明文档保留了早期无法取得社区正文的核对背景，后续全流程整理应结合各自来源理解，不能扩大为所有流程均已验证。

### 3.3 触控布局与标签

保留既有移动端操作方式，优化游戏画面占用及工具入口位置；战斗触控按钮补充“攻击”“跳跃”“打坐”“武功1”至“武功5”等中文标签，配置脚本为 `tools/configure_mobile_skill_labels.py`。这些变化不是重新设计战斗规则，也不表示所有屏幕比例、手势和按键布局已逐一验收，实际显示以设备及游戏内布局为准。

### 3.4 local4 用户图标适配

local4 使用用户提供的 902×917 图片作为图标来源，保留银剑、金色“2”和“剑侠情缘”标题，等比缩放并增加墨绿色留边，适配圆形及圆角方形裁切。

`tools/apply_user_app_icon.py` 对应五档密度的传统图标、圆形图标和自适应前景，共 15 张 PNG，并调整自适应背景。原图、旧图标备份、参数和预览由 LOCAL4 指向 `artwork/user-icon-v4/`。

这是用户图片的尺寸与裁切适配，**不是本轮调用模型生图**。LOCAL3 中的生图测试失败记录不应描述为成功产出。local4 不改变游戏、离线攻略、修改器与操作方式。

## 4. 架构与关键文件

整体由 Android Java 宿主、SDL/JNI 原生引擎、本地游戏资源与整合构建工具组成。Gradle 构建 Java 层和 CMake 原生库，将双 ABI 库、资源及离线攻略打入单 APK。原生侧采用 C++17，并依赖上游第三方库及对应 ABI 的预编译依赖；只有 Android Java 目录不能独立完成构建。

| 路径 | 职责与改造概述 |
| --- | --- |
| `upstream/android/app/src/main/java/com/upwinded/jxqy/JxqyActivity.java` | SDL 宿主、左上角工具入口、PopupMenu、攻略跳转与修改器原生调用 |
| `upstream/android/app/src/main/java/com/upwinded/jxqy/GuideActivity.java` | 离线攻略展示与检索相关界面 |
| `upstream/android/app/src/main/AndroidManifest.xml` | Activity、图标、设备能力和应用声明 |
| `upstream/android/app/build.gradle` | 本地包名、版本、SDK、双 ABI、构建类型与环境变量签名配置 |
| `upstream/android/app/jni/` | Android 原生构建入口，衔接上游引擎与依赖 |
| `upstream/android/app/src/main/res/mipmap-*` | 用户图标的传统、圆形与自适应资源 |
| `upstream/android/app/src/main/res/values/ic_launcher_background.xml` | 自适应图标背景 |
| `tools/stage_local_resources.py` | 校验和暂存资源、应用累积更新、准备攻略与标签 |
| `tools/configure_mobile_skill_labels.py` | 移动端战斗按钮中文标签 |
| `tools/assemble_offline_guide.py` | 合并主线与操作风险说明 |
| `tools/local-build.init.gradle` | 指定本机 NDK/CMake 版本及本地 assets 目录 |
| `tools/build_local_android.py` | 设置工具链与签名环境，调用 Gradle |
| `tools/verify_integrated_apk.py` | 不安装、不运行 APK 的资源及 ZIP 检查 |

此表是架构与重点改造位置概述，不是完整逐文件差异清单。Android 到引擎的接口需要配套原生实现，不能仅复制 Java 菜单代码。

## 5. 环境与构建

### 5.1 前置条件

1. 准备基线一致的完整上游源码、第三方依赖及本地改造代码。正式复现时应进一步核实 `addd0add...` 对应的完整提交 ID。
2. 准备 Python 3、JDK 21、Android SDK 平台 36、相应 Build Tools、Gradle wrapper 所需组件及可用依赖源。现有 Android Gradle Plugin 声明为 `9.3.2`，需与项目 wrapper 和 JDK 配套。
3. 本地初始化脚本指定 NDK `29.0.13113456`、CMake `3.31.6`；应安装对应组件，或在确认兼容性后调整。
4. 自行合法准备脚本要求的资源包、累积更新和引擎资源。资源暂存脚本从 `delivery/resources/` 读取资源，并引用 `downloads/jxqy2-update-20261106/jxqy2-cumulative-20261023.zip`。公开代码仓库不包含原版素材，因此不是仅拉取代码即可构建含完整素材 APK。

### 5.2 必须配置的机器路径

`tools/build_local_android.py` 包含原构建机的绝对路径：

```text
JAVA = C:/Users/lxx/.codex/tools/rea/jdk-21.0.13+9
SDK  = F:/aiworkspace/codexworkspace/worktools_image_suite/worktools_image_suite/mobile_android/.android-sdk
```

换机时必须将 `JAVA`、`SDK` 改为本机有效位置。脚本主动设置 `JAVA_HOME`、`ANDROID_HOME`、`ANDROID_SDK_ROOT`，仅在外部设置这些环境变量不会覆盖硬编码。脚本调用 `gradlew.bat`，属于 Windows 构建入口；其他系统需调整调用方式。其他 tools 脚本的资源、图标与输入路径也应先核对，不可直接照搬机器路径。

### 5.3 构建顺序

在配置好资源、工具链和独立签名方案后，于项目根目录执行：

```powershell
Set-Location 'F:/aiworkspace/codexworkspace/rea/JX2'
python tools/stage_local_resources.py
python tools/assemble_offline_guide.py
python tools/build_local_android.py
```

资源暂存目录为 `build-local/assets`。暂存脚本拒绝覆盖已存在的目录；遇到已有目录，应先确认来源和内容、备份后按需要重建，不应盲目删除。初次暂存放入简明攻略，随后必须执行合并脚本，才能包含全主线整理。复现 local4 应保留已适配的用户图标；重新适配前先核对 `tools/apply_user_app_icon.py` 的输入与参数。

构建脚本的核心任务为：

```text
upstream/android/gradlew.bat -p upstream/android -I tools/local-build.init.gradle -PjxqyAssetsDir=<本机项目绝对路径>/build-local/assets :app:assembleFullyRelease --console=plain --max-workers=4
```

示意中的 assets 路径必须替换为本机绝对路径。实际包装脚本使用绝对路径传递工程、初始化脚本和资源目录。使用 `assembleFullyRelease` 构建内置资源版本，不应将其他构建类型误认为相同交付物。取得 Gradle 输出后再按交付命名归档，不应仅凭文件名判断版本或签名。

离线检查示例：

```powershell
python tools/verify_integrated_apk.py '<实际APK路径>'
Get-FileHash '<实际APK路径>' -Algorithm SHA256
```

另使用本机 Build Tools 的 `apksigner verify --verbose` 验证签名，使用 `aapt2` 核对包名、版本、ABI 与图标引用。新环境、依赖或签名生成的 APK 不保证逐字节复现当前交付包；本文大小与 SHA-256 仅标识当前 local4 文件。

### 5.4 独立签名与保密边界

本地包使用独立签名，不是官方签名。构建脚本在本机 `.local-signing/` 管理签名材料，通过 `JXQY_ANDROID_KEYSTORE`、`JXQY_ANDROID_KEY_ALIAS`、`JXQY_ANDROID_STORE_PASSWORD`、`JXQY_ANDROID_KEY_PASSWORD` 等环境变量交给构建配置。私钥、口令和凭据不公开、不提交，也不随代码文档交付。

已有记录的公开证书 SHA-256 指纹为 `14e03bdbcdb840293e22eed9868cf77e627628af48de44cf2c739f6a9d4ac488`。指纹不是私钥。换机首次生成的新密钥不等于既有交付签名；只有相同包名和签名才能正常覆盖既有本地版，不应通过卸载旧版绕过签名差异而忽略存档风险。

## 7. 安装与存档注意

1. 从 `F:/aiworkfb/剑侠情缘2手机版交付` 获取 local4 APK，核对版本、大小与 SHA-256。该路径是本地交付位置，不是公开素材下载地址。
2. 已安装此前同签名本地版时，优先直接覆盖安装，不要先卸载。仍应事先备份重要存档，不能把通常保留数据理解为无条件保证。
3. 原版、不同签名或不同包名版本的存档不保证自动迁移。卸载、清除数据、系统清理和错误替换资源可能导致丢档；手动迁移前保留完整备份，不覆盖唯一进度。
4. 若启动器缓存旧图标，先确认版本为 `1.2.1-local4`，再返回桌面或重启设备，不要为刷新图标卸载游戏。
5. 在重要场景切换、不可逆选择和剧情战斗前保留多个独立存档。作弊可能影响依赖受伤、敌人存活或特定击败顺序的剧情，尤其唐门被擒等情节；卡住时先关闭无敌/作弊并回读较早进度，避免盲目清场。
6. 单 APK 离线整合不取消素材权利限制。不得把本地 APK、原版资源、签名私钥或个人存档加入公开代码仓库，公开范围保持为代码与文档。

## 8. 交付结论

当前成果是基于上游 GPLv3 引擎的 Android 本地改造，包括单 APK 离线整合、左上角攻略/修改器入口、主线资料整理、触控布局与标签优化，以及用户图标适配。它不是官方手游，也不是已完成全流程、全机型或完整 GUI 认证的产品。真实设备上的菜单、攻略检索、修改器、触控、关键剧情及更广设备覆盖仍需后续验收。
